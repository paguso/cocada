# cocadoc

Documentation generator for COCADA, written with COCADA.

It reads C headers, pairs each documentation comment with the declaration
that follows it, checks the comments against the COCADA documentation comment
style (`../doc/comment-style.md`), and writes one Markdown page per header.

## Build

```
make build    # build/debug/cocadoc
make test     # build/test/test (unit tests)
```

## Use

cocadoc is configured by a `cocadoc.config` file. COCADA's is at the root of
the repository:

```
PROJECT_NAME = COCADA
VERSION = 0.5.0                 // may be empty
OUTPUT_TYPE = markdown          // only markdown for now
OUTPUT_DIRECTORY = ./doc/markdown
BASE_DIR = ./
MODULES = libcocada libcocadaapp libcocadabio libcocadasketch libcocadastrproc
EXCLUDE_DIRS = thrdpty          // may be empty
EXCLUDE_FILES =                 // patterns, e.g. *deprecated.h *temporary.h
```

Text after `//` is a comment, lists are separated by spaces, and paths are
relative to the configuration file. The headers documented are the `*.h`
files found recursively in each `BASE_DIR/MODULE/src/`, except those in
directories named in `EXCLUDE_DIRS` (at any depth) and those whose names
match a pattern of `EXCLUDE_FILES`.

From the root of the repository:

```
cocadoc/build/debug/cocadoc         # write the pages to OUTPUT_DIRECTORY
cocadoc/build/debug/cocadoc -l      # only check the comments against the style
cocadoc/build/debug/cocadoc -c path/to/other.config
```

Headers can also be given explicitly, instead of those listed by the
configuration. All references between headers (`#name`, `@see`, `name.h`)
are resolved among the files documented together, so give them all at once:

```
cocadoc/build/debug/cocadoc -o /tmp/docs libcocada/src/container/vec.h libcocada/src/core/new.h
```

Options:

| option | does |
|---|---|
| `-c FILE`, `--config FILE` | configuration file (default: `./cocadoc.config`, if any) |
| `-o DIR`, `--output DIR` | write the pages to `DIR` (default: `OUTPUT_DIRECTORY`) |
| `-l`, `--lint` | print style warnings as `file:line: warning: [DCn] name: message`, and a count per rule |
| `-s`, `--symbols` | dump the symbol table (debug) |
| `-D`, `--docs` | dump the parsed doc comments (debug) |
| `-d`, `--decls` | dump the declarations (debug) |
| `-t`, `--tokens` | dump the tokens (debug) |
| `-v`, `--version` | print the version |
| `-h`, `--help` | print the help |

Pages are written when `-o` is given, or by default when documenting the
configuration's headers without any of `-l`, `-s`, `-D`, `-d`, `-t`.

## Pages

`index.md` has a section for each module, with a nested list of its
directories and headers, and their briefs. The title is
`PROJECT_NAME VERSION API Reference`.

Each header gets a page (`vec.h` → `vec.md`) with:

- the header name, brief and authors, and links to the description, the
  contents, and the module in the index;
- **Description**: the module documentation (the header's file comment);
- **Contents**: the types and constants, functions and macros, with their
  briefs;
- a section for each of these groups, with each item's declaration and
  documentation: brief, details, parameters (marked **(moved)** for
  `@param @move`), return value, warnings, notes, deprecation and see-also,
  followed by a link back to the contents;
- a footer with the cocadoc version.

Missing documentation is shown as *undocumented*. Links use the heading
anchors generated by GitLab and GitHub, e.g. `vec.md#vec_new`. References to
struct fields and enum constants link to their type.

## Source

| module | does |
|---|---|
| `cdconfig` | reads `cocadoc.config` and finds the headers |
| `cdversion` | the version of cocadoc |
| `cdlexer` | splits C source into tokens (doc comments and preprocessor lines are single tokens) |
| `cddecl` | pairs doc comments with declarations, and classifies them |
| `cddoc` | parses a doc comment into fields, and checks the per-comment rules |
| `cdfile` | a loaded header: contents, tokens and declarations |
| `cdsym` | symbol table of all the headers, to resolve references |
| `cdlint` | checks that need the declarations and the symbol table |
| `cdmd` | writes the Markdown pages |
